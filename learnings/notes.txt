═════════════════════════════════════════════════════════════════════════════════════════════════════════
         PYTORCH CORE LESSON: tensor.max() vs. tensor.max().item()
═════════════════════════════════════════════════════════════════════════════════════════════════════════
• `batch['lr'].max()`:
  - Returns a `torch.Tensor` object (e.g. `tensor(13.6226)`).
  - Lives on whatever device the tensor is on (CPU or GPU `cuda:0`).
  - Retains autograd computation graph history.
  - CRITICAL WARNING: In training loops, never do `loss_history.append(loss)`. 
    Because it is a tensor attached to autograd, PyTorch keeps the entire backward graph in 
    GPU memory across every batch, leading to a fatal CUDA Out-of-Memory (OOM) crash!

• `batch['lr'].max().item()`:
  - Extracts the scalar and converts it into a native Python primitive `float` (e.g. `13.62263011932373`).
  - Completely detached from PyTorch, devices, and computation graphs.
  - Safe for string formatting (`f"{val:.4f}"`), logging, and storing: `loss_history.append(loss.item())`.
  - Constraint: `.item()` can ONLY be called on 1-element tensors (scalars). Calling it on a 
    multi-element tensor raises ValueError.


═════════════════════════════════════════════════════════════════════════════════════════════════════════
   MASTER REFERENCE: DATA TRANSFORMATION & NORMALIZATION PLAYBOOK FOR ALL DATA MODALITIES
═════════════════════════════════════════════════════════════════════════════════════════════════════════

This playbook defines when to use Curve Transformations, when to use Normalization, and how 
different data types (Tabular, Image, Text, Audio, Time-Series) must be preprocessed.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
1. TABULAR DATA (Prices, Salaries, Measurements, Financials, Health Metrics)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Characteristics:
  - Continuous 1D numbers, frequently exhibiting severe right-skew and multi-magnitude spreads.
  - Different columns have totally different units (e.g., Age: 20-80 vs. Income: $30,000-$5,000,000).

• The Two-Step Playbook: YOU DO BOTH (Curve Transform + Normalization):
  1. Step 1 (Fix the Shape / Curve):
     - Log Transform: `y = log(1 + x)` (compresses extreme right tails).
     - Box-Cox Transform (requires strictly positive numbers x > 0).
     - Yeo-Johnson Transform (PowerTransformer, handles zeros and negative numbers).
  2. Step 2 (Fix the Scale / Units):
     - `StandardScaler`: Centers at mean=0, scales to std=1.
     - `MinMaxScaler`: Scales to [0, 1] or [-1, 1].
     - `RobustScaler`: Uses Median and Interquartile Range (IQR); best for heavy outliers.

• Model Distinction:
  - Linear Models (OLS, Ridge, Lasso, Logistic), KNN, SVM, MLPs: MANDATORY to do both.
  - Tree-Based Models (Decision Trees, Random Forest, XGBoost, LightGBM): NO transforms needed!
    Trees only split on ordering (`feature > threshold`); curve and scale changes have zero effect.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
2. COMPUTER VISION & SATELLITE IMAGERY (Photos, GeoTIFFs, Video, Medical Imaging)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Characteristics:
  - 2D/3D grids where neighboring pixels form spatial edges, textures, and convolutions.
  - Pixel values represent physical electromagnetic radiation (photons).

• The Playbook: LINEAR NORMALIZATION ONLY (NO Curve Transforms):
  1. Step 1 (Range Scaling):
     - 8-bit standard images: Divide by 255.0 -> [0.0, 1.0].
     - 12-bit satellite images: Divide by 10,000.0 (SentinelHub dynamic range) -> [0.0, 1.0].
     - Medical CT/MRI Scans: Apply Hounsfield Windowing (e.g. Brain window: [0, 80]), then scale.
  2. Step 2 (Input Normalization):
     - Per-channel Z-score: `Normalize(mean, std)` to center around 0 and scale variance to 1.
  3. Ground-Truth Targets:
     - Keep strictly in [0.0, 1.0] (with `.clamp(min=0, max=1)`) to match output activations (Sigmoid).
  • CRITICAL RULE: NEVER apply non-linear Log or Box-Cox transforms to raw image pixels!
    Warping the curve destroys optical contrast ratios and degrades edge detection filters.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
3. TEXT / NATURAL LANGUAGE PROCESSING (NLP & LLMs)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Characteristics:
  - Discrete symbols (words, subword tokens, characters), NOT continuous numerical curves.
  - Word distributions follow Zipf's Law (exponential power-law frequency).

• The Playbook: TOKENIZATION -> EMBEDDINGS -> LAYER NORMALIZATION:
  1. Classical NLP (Logistic Regression, Naive Bayes):
     - Tokenize words -> Compute TF-IDF (Term Frequency-Inverse Document Frequency).
     - Normalize document vectors using L2 norm (`||v||_2 = 1`).
  2. Modern Deep Learning & Large Language Models (Transformers, GPT, BERT):
     - Text -> Subword Tokenizer (BPE, WordPiece) -> Token IDs.
     - Token IDs map into a high-dimensional dense Embedding Matrix: Token ID -> vector in R^d.
     - Internal Normalization: `LayerNorm` or `RMSNorm` applied across the hidden dimension of each
       token before self-attention to stabilize gradient backpropagation.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
4. AUDIO & SPEECH PROCESSING (Audio Waveforms, Speech-to-Text, Music AI)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Characteristics:
  - Raw 1D sound wave oscillating around 0 (amplitudes in [-1.0, +1.0]).
  - Human hearing perception is logarithmic (we hear loudness in decibels, pitch in octaves).

• The Playbook: SPECTROGRAM -> LOG-MEL TRANSFORM -> Z-SCORE:
  1. Short-Time Fourier Transform (STFT): Converts 1D raw waveform into 2D time-frequency spectrogram.
  2. Mel-Scale Filterbanks: Remaps frequencies to human-audible Mel scale.
  3. Log (Decibel) Transform (THE ONLY DOMAIN WHERE LOG IS STANDARD ON "IMAGES"):
     - Apply `10 * log10(Power + eps)` to convert power to Decibels (dB).
     - Because human ears perceive sound logarithmically, this log step is acoustically necessary.
  4. Normalization: Standardize log-mel spectrogram with mean=0, std=1 across frequency bins.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
5. TIME-SERIES & SENSOR DATA (Stock Market, IoT Sensors, Energy Demand, Weather)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Characteristics:
  - Sequential data indexed by time with trends, seasonality, and non-stationarity.

• The Playbook: STATIONARITY TRANSFORM -> ROLLING NORMALIZATION:
  1. Step 1 (Remove Trends / Make Stationary):
     - Differencing: `y_diff = y_t - y_{t-1}` (removes linear upward/downward drift).
     - Percentage / Log-Returns: `r_t = log(P_t / P_{t-1})` (standard in financial prices).
  2. Step 2 (Normalization):
     - Apply Rolling / Windowed `StandardScaler` or `MinMaxScaler`.
  • CRITICAL RULE: Never normalize using the entire time-series at once! Doing so causes 
    "Look-Ahead Bias / Data Leakage" (future information leaks into past timestamps). Always 
    fit scalers ONLY on past training windows.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
SUMMARY CHEAT SHEET MATRIX
─────────────────────────────────────────────────────────────────────────────────────────────────────────
Data Modality   │ Curve Transform? (Log/Box-Cox) │ Normalization Method      │ Primary Goal
────────────────┼────────────────────────────────┼───────────────────────────┼───────────────────────────
Tabular (Linear)│ YES (Log / Box-Cox on skew)    │ StandardScaler / Robust   │ Make residuals Gaussian
Tabular (Trees) │ NO (Not needed)                │ NONE needed               │ Split on ordinal rank
Images / Video  │ NO (Destroys optical contrast) │ Max Scaling + Z-score     │ Center zero & stabilize
Text (LLMs)     │ NO (Discrete tokens)           │ LayerNorm / RMSNorm       │ Stabilize self-attention
Audio (Speech)  │ YES (Log-Mel Decibel scale)    │ Z-score on spectrogram    │ Match human ear acoustics
Time-Series     │ YES (Differencing / Log-Return)│ Rolling StandardScaler    │ Remove trend leakage


═════════════════════════════════════════════════════════════════════════════════════════════════════════
   SATELLITE REMOTE SENSING DEEP DIVE: 12 MULTI-SPECTRAL INPUT BANDS VS. 3 RGB OUTPUT BANDS
═════════════════════════════════════════════════════════════════════════════════════════════════════════
Why feed 12 input bands if the model only predicts 3 RGB output bands?

At first glance, feeding 12 input bands just to predict 3 RGB output bands sounds like a waste 
of compute and bandwidth. However, in satellite remote sensing, those extra 9 non-visible bands 
provide critical physical signals that visible light cannot capture, directly improving the 
sharpness, de-hazing, and material fidelity of the reconstructed RGB image.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
1. Penetrating Atmospheric Haze and Thin Cirrus Clouds (SWIR & Cirrus Bands)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Short-wavelength visible light (Bands 2, 3, 4: 450–660 nm) suffers heavily from Rayleigh and aerosol
  scattering in the atmosphere. Humidity, haze, and thin cirrus clouds blur and scatter visible RGB pixels.
• In contrast, Short-Wave Infrared (SWIR: Bands 11 & 12, 1610–2190 nm) and Near-Infrared (NIR: Band 8, 842 nm)
  have much longer wavelengths that cut straight through aerosol particles and smoke.
• The Network Advantage:
  When an RGB pass is blurry or hazy, the neural network extracts the sharp ground geometry and building
  outlines from the penetrating SWIR and NIR channels, using that structural guide to de-haze and reconstruct
  crisp visible RGB edges:

  Visible RGB:   [ Blurry / Hazy from atmospheric Rayleigh scattering ] ──┐
                                                                          ├─► [Feature Encoder] ──► Sharp RGB
  Infrared/SWIR: [ Cuts through haze; detects sharp structural boundaries] ──┘

─────────────────────────────────────────────────────────────────────────────────────────────────────────
2. Disambiguating Visually Identical Materials (Physical Spectral Signatures)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
In standard RGB, completely different physical materials often share identical pixel colors:
• A green artificial turf roof and a natural grass lawn look like the exact same green in RGB.
• Clear deep water, asphalt roads, and building shadows all appear as identical dark/black pixels in RGB.

How the non-visible bands disambiguate them:
• The "Red-Edge" Jump (Bands 5, 6, 7 & 8): Living vegetation reflects up to 50% of NIR light due to
  spongy mesophyll leaf cell structures, whereas artificial plastic turf reflects almost none.
• SWIR (Bands 11 & 12): Pure water absorbs 100% of infrared radiation (pitch black), whereas asphalt,
  concrete, and dry soil reflect strongly.
• The Network Advantage: By analyzing all 12 bands, the network understands the physical material
  class of each surface, preventing it from blurring roads into water or smudging building outlines.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
3. Computational Cost is Negligible (<0.05% of Total Model Parameters)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
Feeding 12 bands instead of 3 does NOT quadruple the model's compute or memory:
• The input channel count ONLY affects the very first 2D convolution layer (`src/modules.py`):
    `self.encoder = DoubleConv2d(in_channels=12, out_channels=hidden_channels)`
• This initial convolution immediately projects the 12 bands down to `hidden_channels = 64`.
• The entire rest of the network—all residual blocks, RecursiveFusion, and PixelShuffle upsamplers—runs
  on `hidden_channels = 64` regardless of whether you fed 3 bands or 12 bands!
• Parameter difference: only ~5,184 additional weights in a multi-million parameter architecture.
• The only practical overhead is disk I/O when reading the extra GeoTIFF channels from storage.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
4. Empirical Performance Gains (WorldStrat & Literature Benchmarks)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
In scientific super-resolution literature (e.g., Razzak et al., 2021 and the WorldStrat benchmark):

  Input Channels Fed              Output Target    Reconstruction Gain (PSNR)
  ───────────────────────────────────────────────────────────────────────────────────────
  Only 3 RGB Bands (B4, B3, B2)   3 RGB Bands      Baseline Reconstruction
  All 12 Multi-Spectral Bands     3 RGB Bands      +0.8 dB to +1.4 dB higher PSNR

The network effectively treats the 9 extra non-visible bands as a free structural and physical guide.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
TAKEAWAY FOR THIS REPOSITORY & TECHNICAL INTERVIEWS
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• For Fast Prototyping (testing.ipynb):
  Using `lr_bands_to_use='true_color'` (3 RGB bands) is practical and fast. It minimizes RAM usage,
  avoids disk I/O bottlenecks, and allows rapid iteration of training loops and loss functions.
• For Technical Interviews:

═════════════════════════════════════════════════════════════════════════════════════════════════════════
   ARCHITECTURAL REALITY: WHY STANDARD PRETRAINED MODELS (ImageNet, ESRGAN, EDSR) CANNOT BE USED DIRECTLY
═════════════════════════════════════════════════════════════════════════════════════════════════════════
Why can't we simply download a pretrained Real-ESRGAN, RCAN, or ResNet from PyTorch or HuggingFace?

In standard Computer Vision, fine-tuning a pretrained model (transfer learning) is the default choice.
However, standard pretrained vision models fail out-of-the-box on this task for 5 fundamental physical 
and architectural reasons:

─────────────────────────────────────────────────────────────────────────────────────────────────────────
1. 5D Multi-Temporal Input Tensors vs. 4D Single Images (MFSR vs. SISR)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Standard Pretrained Models (Single-Image Super-Resolution / SISR: EDSR, ESRGAN, RCAN):
  - Expect a 4D tensor: `(Batch, Channels=3, Height, Width)`. They only accept ONE image at a time.
• Our Satellite Task (Multi-Frame Super-Resolution / MFSR: HighResNet):
  - Ingests a 5D tensor: `(Batch, Revisits=8, Channels=3/12, Height=160, Width=160)`.
  - The model must fuse 8 temporal revisits across different dates, aligning sub-pixel orbital shifts
    and selecting clear pixels across cloudy revisits via specialized modules (`RecursiveFusion`).
  - Standard 2D convolution layers literally cannot accept a 5D input without crashing on tensor shape.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
2. Auxiliary Cloud Mask Condition (`batch['lrc']`)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Standard models have NO mechanism to accept a separate pixel-level mask tensor.
• In satellite imagery, clouds partially cover the ground on different dates. HighResNet accepts the
  cloud mask (`mask_channels=1`) to weight and mask out cloudy revisit pixels during temporal fusion.
  A standard pretrained model would treat cloudy pixels as real ground textures, creating blurry artifacts.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
3. Arbitrary / Non-Integer Upscaling Factor (6.6667x vs. Standard 2x / 4x / 8x)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Standard super-resolution models rely on fixed-integer PixelShuffle or transposed convs (2x, 4x, or 8x):
    160x160 -> 320x320 (2x), 640x640 (4x), or 1280x1280 (8x).
• The physical reality of WorldStrat:
  - Input: Sentinel-2 Ground Sampling Distance = 10 meters / pixel (160x160).
  - Target: Airbus SPOT Ground Sampling Distance = 1.5 meters / pixel (1054x1054).
  - Exact Physical Scale Factor: 10m / 1.5m = 6.6667x!
• An off-the-shelf 4x model outputs 640x640 (under-resolved), while an 8x model outputs 1280x1280 (mismatched).
  The architecture must be custom-configured to project to the exact target size `(1054, 1054)`.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
4. Geolocation Parallax & Sub-Pixel Misregistration (Why Standard Losses Fail)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Consumer photos in ImageNet / DIV2K have perfect 1:1 pixel alignment between LR and HR (synthetically
  created by downsampling HR using bicubic filters).
• Real satellite images (Sentinel-2 and SPOT) are captured by two different satellites in different orbits:
  - Even after GIS georeferencing, there are natural 1-2 pixel sub-pixel registration shifts due to
    topography, atmospheric refraction, and orbital angles.
• If you train a standard model with standard MSE or L1 loss on real satellite pairs:
  - Standard MSE severely penalizes the 1-pixel shift, causing the network to output a completely blurred,
    foggy average to minimize pixel-to-pixel error!
  - This project requires shift-invariant registered loss (cR-loss / cyclic registration loss in `src/losses.py`),
    which searches over a ±2 px window to calculate error invariant to sub-pixel misalignment.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
5. Multi-Spectral Radiometry (12 Bands & 12-Bit Depth vs. 8-Bit sRGB)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• ImageNet / consumer models are pretrained on 8-bit JPEG photography with human-eye sRGB gamma curves.
• Earth observation satellites capture linear physical surface reflectance across 12 bands (including
  Red-Edge and SWIR) with up to 16-bit dynamic ranges. Standard pretrained weights for 3-channel sRGB
  have zero physical understanding of infrared absorption or reflectance physics.

1. The Real-World Analogy: Studying with Flashcards
─────────────────────────────────────────────────────────────────────────────────────────────────────────
Think of your 3,927 satellite scenes as a giant deck of flashcards:

• Step 1: `random_split` is DEALING THE DECK (Happens ONCE):
  - You deal 80% of the cards into your Study Pile (`train_set`).
  - You deal 10% into your Practice Quiz Pile (`val_set`).
  - You deal 10% into your Final Exam Pile (`test_set`).
  - Strict Rule: These cards NEVER cross over! A card from the Final Exam pile must never sneak into 
    your Study Pile. If it does, that is fatal DATA LEAKAGE (the model cheats on the test).

• Step 2: `DataLoader` is HOW YOU READ THE CARDS during each study session:
  - For Training (`shuffle=True`):
    * Round 1 (Epoch 1): You draw cards in order: [A, B], [C, D], ...
    * Round 2 (Epoch 2): You re-shuffle your study pile: [C, A], [D, B], ...
    * Why? If you never shuffle between epochs, the neural network learns to memorize the exact sequence 
      of cards rather than learning actual satellite feature representations.
  - For Validation & Testing (`shuffle=False`):
    * The practice test must have the EXACT SAME questions in the EXACT SAME order every single epoch.
    * That way, if your PSNR metric goes from 24.5 dB -> 27.8 dB, you know with 100% scientific certainty 
      that the model actually improved, rather than just getting an easier sequence of questions!

─────────────────────────────────────────────────────────────────────────────────────────────────────────
2. Technical Scope: Why Can't One Function Do Both?
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• `random_split` only divides indices:
  - It creates PyTorch `torch.utils.data.Subset` objects wrapping index lists.
  - It has zero concept of mini-batches, GPU memory pinning, or multi-threaded worker loading.
  - It does NOT iterate or load images into memory.

• `DataLoader` only batches a single given dataset:
  - It has no concept of "train vs. val vs. test".
  - It can only ingest a single dataset object and slice it into mini-batches of size N (`batch_size=2`).
  - It cannot divide one dataset into three separate subsets.

Separating them gives you complete control over:
1. WHAT DATA GOES WHERE (`random_split` ensures zero data leakage).
2. HOW DATA IS SERVED (`DataLoader` manages batching, workers, and epoch-level re-shuffling).

─────────────────────────────────────────────────────────────────────────────────────────────────────────
3. Guaranteeing 100% Deterministic Reproducibility
─────────────────────────────────────────────────────────────────────────────────────────────────────────
By default, Python and PyTorch use pseudo-random state that changes every time a script is re-run.
To ensure that your Train/Val/Test splits and batch shuffles are identical every single time:

1. Pass an explicit generator to `random_split`:
   `split_gen = torch.Generator().manual_seed(42)`
   `train_set, val_set, test_set = random_split(dataset, lengths, generator=split_gen)`

2. Pass an explicit generator and worker_init_fn to `DataLoader`:
   `loader_gen = torch.Generator().manual_seed(42)`
   `DataLoader(train_set, shuffle=True, generator=loader_gen, worker_init_fn=seed_worker)`

─────────────────────────────────────────────────────────────────────────────────────────────────────────
2. Deep Dive: The 3 Core Pillars
─────────────────────────────────────────────────────────────────────────────────────────────────────────

PILLAR 1: THE PER-FRAME FEATURE ENCODER
• Channel Fusion:
  - Concatenate image channels (3 RGB) with cloud mask (1 channel) along channel dimension:
    `C_in = 3 + 1 = 4` channels.
• The Multi-Revisit Trick (Batch Flattening):
  - Standard 2D convolutions (`Conv2d`) expect 4D tensors `(Batch, Channels, H, W)`.
  - Input is 5D: `(B, T, C, H, W)` where T=8.
  - Flatten B and T together: `x = x.view(B * T, C, H, W)`.
  - Process all 8 revisits in parallel through 2D convolutions, then reshape back:
    `encoded = encoded.view(B, T, hidden_channels, H, W)`.
• Output: `(B, 8, 64, 160, 160)`.

PILLAR 2: RECURSIVE LATENT FUSION UNIT
• Why Recursive?
  - Simple temporal averaging blurs edges and blends clouds into clear skies.
  - HighResNet maintains a running latent hidden state `h` representing the ground truth estimate.
• The Recurrent Loop:
  - For each revisit t in [0, 7]:
    * Ingest current revisit features `e_t` and running hidden state `h_{t-1}`.
    * Concatenate them along channel axis: `[h_{t-1}, e_t]` -> 128 channels.
    * Pass through a Convolutional Fusion Block: projects 128 channels back to 64 channels.
    * Update state: `h_t = FusionBlock([h_{t-1}, e_t])`.
• State Initialization:
  - `h_0` can be initialized as zeros `torch.zeros(B, 64, 160, 160)` or as the first frame's features `e_0`.
• Output: Fused latent state `(B, 64, 160, 160)`.

PILLAR 3: SUPER-RESOLUTION RECONSTRUCTION HEAD
• The Upscaling Ratio Challenge:
  - Input size: 160 x 160. Target size: 1054 x 1054.
  - Scale factor: 1054 / 160 = 6.5875x (non-integer upscaling).
• Upscaling Strategy:
  - Option A: Sub-pixel convolution (`nn.PixelShuffle(upscale_factor=4 or 8)`) followed by
    `F.interpolate(size=(1054, 1054), mode='bicubic')` for the final exact dimension.
  - Option B: Latent interpolation up to (1054, 1054) followed by refining residual Conv2d blocks.
• Physical Range Guard:
  - The ground-truth target is normalized to [0.0, 1.0].
  - The final layer must use `nn.Sigmoid()` to strictly constrain predicted reflectance values
    to [0.0, 1.0], preventing negative reflectance or blown-out highlights.

4. Deep Dive: Tournament-Style Binary Tree Fusion (8 -> 4 -> 2 -> 1)
─────────────────────────────────────────────────────────────────────────────────────────────────────────

Rather than processing the 8 revisits in a linear sequential chain (Revisit 0 -> 1 -> 2 -> ... -> 7),
HighResNet uses a tournament-style binary fusion tree:

Revisits:    [F0] [F1]   [F2] [F3]   [F4] [F5]   [F6] [F7]
               └──┬──┘     └──┬──┘     └──┬──┘     └──┬──┘
Round 1:         [S0]        [S1]        [S2]        [S3]    (8 revisits -> 4 states)
                   └───┬───────┘           └───┬───────┘
Round 2:              [S0]                    [S1]            (4 states -> 2 states)
                        └──────────┬───────────┘
Round 3:                          [SF]                        (2 states -> 1 Final Master State)

Why the Tournament Tree is Structurally Superior:
1. Logarithmic Gradient Depth:
   - Linear sequential chains have a recurrent depth of T = 8 steps, leading to vanishing/exploding gradients.
   - The tournament tree has a depth of only log2(8) = 3 rounds! Gradients backpropagate easily to all frames.
2. Temporal Permutation & Order Symmetry:
   - Revisits arrive at irregular intervals. Linear recurrent models artificially bias toward the most recent
     revisit. The tournament tree treats pairs symmetrically, ensuring all 8 revisits contribute equally.
3. Clean Algorithmic Implementation:
   - In PyTorch, this is implemented as a simple loop:
     while len(frame_list) > 1:
         frame_list = [fusion_block(frame_list[i], frame_list[i+1]) for i in range(0, len(frame_list), 2)]

═════════════════════════════════════════════════════════════════════════════════════════════════════════

During the reverse-engineering of `src/modules.py` from the official WorldStrat repository,
a critical code audit revealed two major bugs and one architectural limitation in their
`BicubicUpscaledBaseline` class:

─────────────────────────────────────────────────────────────────────────────────────────────────────────
1. Bug 1: Inverted Order-of-Operations in De-Normalization (The Smoking Gun)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• In the official WorldStrat source code:
  Line 28 Comment:  `# De-normalize back to original reflectance space (x * std + mean)`
  Line 30 Code:     `x += torch.as_tensor(self.mean[...]).to(device)`
  Line 31 Code:     `x *= torch.as_tensor(self.std[...]).to(device)`

• The Mathematical Error:
  - Input normalization was: z = (x - mean) / std.
  - Correct inversion:      x = (z * std) + mean.
  - What their code did:    x_err = (z + mean) * std = (z * std) + (mean * std).
  The author wrote the correct formula in the comment, but wrote Python statements in the reverse order!
  This incorrectly scales the mean offset by the standard deviation.

• The Correction:
  `x = (x * self.std) + self.mean`

─────────────────────────────────────────────────────────────────────────────────────────────────────────
2. Bug 2: Radiometric Destruction via `x /= torch.max(x)`
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• In the official WorldStrat source code:
  Line 34: `x /= torch.max(x)`
  Line 35: `torch.clamp_(x, 0, 1)`

• The Scientific Problem:
  - Both Sentinel-2 and SPOT measure absolute physical surface reflectance in [0.0, 1.0].
  - Dividing an image by its local maximum pixel destroys calibrated physical surface reflectance.
  - Example: A dark agricultural field or ocean tile with true max reflectance = 0.18 will be stretched
    so 0.18 -> 1.00 (turning dark water or green vegetation bright white).
  - This is an old Matplotlib visualization hack that breaks quantitative PSNR and MSE metric evaluation.

• The Correction:
  Remove `x /= torch.max(x)` entirely. Simply clamp to [0.0, 1.0]:
  `x = x.clamp(min=0.0, max=1.0)`

─────────────────────────────────────────────────────────────────────────────────────────────────────────
3. Limitation: Revisit 0 Selection vs. Temporal Median
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Their class selects only the first revisit: `x = x[:, 0, :]`.
• If revisit 0 happens to have cloud cover or haze, the entire baseline prediction is clouded.
• The paper text states that calculating the temporal median across all 8 revisits provides a far
  stronger baseline because it naturally filters out transient clouds and shadows.
• The Correction:
  `x = torch.median(x, dim=1).values`

═════════════════════════════════════════════════════════════════════════════════════════════════════════
   THEORETICAL FOUNDATION: WHY DE-NORMALIZATION IS MANDATORY IN HEURISTIC BASELINES
═════════════════════════════════════════════════════════════════════════════════════════════════════════

Why do we explicitly de-normalize `x = (x * std) + mean` inside `BicubicUpscaledBaseline`?
Why can't we simply upscale the low-resolution input tensor directly?

─────────────────────────────────────────────────────────────────────────────────────────────────────────
1. The "Apples to Oranges" Domain Mismatch
─────────────────────────────────────────────────────────────────────────────────────────────────────────
Look at what is stored inside the input versus the target tensors inside the DataLoader:

┌───────────────────────────────────────┬───────────────────────────────────┬───────────────────────────┐
│ Tensor                                │ Physical Meaning                  │ Numerical Range           │
├───────────────────────────────────────┼───────────────────────────────────┼───────────────────────────┤
│ Input: `batch['lr']`                  │ Abstract Z-Scores (Standard       │ ~ [-0.5 to +12.0]         │
│ (Sentinel-2)                          │ deviations centered at mean = 0)  │                           │
├───────────────────────────────────────┼───────────────────────────────────┼───────────────────────────┤
│ Target: `batch['hr_pansharpened']`    │ True Physical Surface Reflectance │ [0.0 to 1.0] (Reflectance │
│ (Airbus SPOT)                         │ (Photons reflected from Earth)    │ calibrated via / 10,000)  │
└───────────────────────────────────────┴───────────────────────────────────┴───────────────────────────┘

Notice: The target was NEVER Z-score normalized! It remains in linear physical reflectance units [0.0, 1.0].

─────────────────────────────────────────────────────────────────────────────────────────────────────────
2. Why Neural Networks Learn the Mapping, But Heuristics Cannot
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Neural Networks (e.g., `HighResNet`):
  - Consist of millions of learnable parameters, convolutional filters, and a final `nn.Sigmoid()` head.
  - Through gradient backpropagation, the neural network autonomously learns the non-linear transfer 
    function that maps Z-score feature representations into physical surface reflectance [0.0, 1.0].
  - The network internally handles the domain conversion.

• Non-Learned Heuristic Baselines (`BicubicUpscaledBaseline`):
  - Have ZERO learnable weights, ZERO neurons, and ZERO intelligence.
  - Bicubic interpolation is purely a polynomial spatial resampling formula that fits cubic splines 
    between neighboring pixel coordinates.
  - If you feed it Z-scores (centered at 0), it will output stretched Z-scores (centered at 0)!
  - It has no capacity to "know" that a Z-score of 0.0 corresponds to a real-world physical 
    reflectance of 14% (0.14).

─────────────────────────────────────────────────────────────────────────────────────────────────────────
3. The Mathematical Consequence of Skipping De-Normalization
─────────────────────────────────────────────────────────────────────────────────────────────────────────
If you skip de-normalization and evaluate your Bicubic baseline directly against the SPOT target:

$$\text{Error} = (\hat{y}_{\text{Bicubic}} - y_{\text{SPOT}})^2$$

You are literally evaluating:
$$(\text{Z-Score of } -0.3) - (\text{Physical Reflectance of } 0.15)$$

This is equivalent to subtracting temperatures in Fahrenheit from temperatures in Celsius!
- Dark areas with negative Z-scores get heavily and artificially penalized.
- High-contrast cloudy areas with Z-scores > 8 blow up the Mean Squared Error (MSE) to catastrophic levels.
- The resulting Peak Signal-to-Noise Ratio (PSNR) and Structural Similarity (SSIM) values become 
  completely unscientific, skewed, and meaningless.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
4. The Golden Rule of Benchmark Evaluation
─────────────────────────────────────────────────────────────────────────────────────────────────────────
Whenever evaluating a non-learned baseline (Bicubic, Bilinear, Nearest Neighbor) against a neural network:
BOTH predictions must be projected into the EXACT SAME physical domain as the ground truth before 
computing error metrics. De-normalizing via `x = (x * std) + mean` restores the low-res image to true 
surface reflectance, guaranteeing a scientifically fair, 1:1 benchmark comparison.


═════════════════════════════════════════════════════════════════════════════════════════════════════════
   PYTORCH TENSOR SLICING MECHANICS: INTEGER INDEXING (COLLAPSING) VS. SLICE INDEXING (PRESERVING)
═════════════════════════════════════════════════════════════════════════════════════════════════════════

Why does `x = x[:, 0, :]` collapse the dimension from 5D to 4D, and why does `x[:, 0:1, :, :, :]` keep it 5D?

─────────────────────────────────────────────────────────────────────────────────────────────────────────
1. The Fundamental Slicing Rule: Integer vs. Slice Range
─────────────────────────────────────────────────────────────────────────────────────────────────────────
Given a 5D Tensor `x` of shape `(Batch, Revisits, Channels, Height, Width)` -> `(2, 8, 3, 160, 160)`:

• Case A: Integer Indexing (`x[:, 0, ...]`) -> COLLAPSES (DROPS) THE DIMENSION:
  - Syntax: Passing a single scalar integer `0` for the revisit axis.
  - Meaning: "Extract element 0 directly."
  - Behavior: Because a single specific element is extracted (rather than a sub-collection), PyTorch 
    completely removes that axis from the tensor shape.
  - Result: Shape drops from 5D to 4D: `(2, 3, 160, 160)`.

• Case B: Slice Range Indexing (`x[:, 0:1, ...]`) -> PRESERVES THE DIMENSION:
  - Syntax: Passing a slice range `0:1` (from index 0 up to, but not including, index 1).
  - Meaning: "Extract a sub-slice of length 1 along this axis."
  - Behavior: Because the slice operator (`:`) was used, PyTorch preserves the rank of the tensor, 
    keeping the axis intact with dimension length 1.
  - Result: Shape remains 5D: `(2, 1, 3, 160, 160)`.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
2. The Implicit Trailing Slices Rule (Why `x[:, 0, :]` works on 5D)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
In Python, NumPy, and PyTorch, any trailing dimensions omitted at the end of a slice are implicitly 
treated as full slices (`:`):

┌────────────────────────────┬─────────────────────────────┬────────────────────────────────────────────┐
│ Slicing Syntax             │ How PyTorch Interprets It   │ Output Shape & Rank                        │
├────────────────────────────┼─────────────────────────────┼────────────────────────────────────────────┤
│ `x[:, 0, :, :, :]`         │ Explicit 5D specification   │ `(B, 3, 160, 160)` (4D, Most readable)     │
│ `x[:, 0, :]`               │ Trailing H & W assumed `:`  │ `(B, 3, 160, 160)` (4D, Lazy shorthand)   │
│ `x[:, 0, ...]`             │ Ellipsis `...` fills rest   │ `(B, 3, 160, 160)` (4D, Idiomatic PyTorch) │
│ `x[:, 0]`                  │ C, H, W all assumed `:`     │ `(B, 3, 160, 160)` (4D, Shortest form)     │
├────────────────────────────┼─────────────────────────────┼────────────────────────────────────────────┤
│ `x[:, 0:1, :, :, :]`       │ Slice range preserves rank  │ `(B, 1, 3, 160, 160)` (5D, Preserves axis) │
└────────────────────────────┴─────────────────────────────┴────────────────────────────────────────────┘

"Explicit is better than implicit" (PEP 20): Writing `x[:, 0, :, :, :]` makes it immediately obvious
to anyone reading your code that `x` is a 5D tensor, whereas `x[:, 0, :]` visually looks like a 3D slice.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
3. Code Case Study: The WorldStrat Redundant 2-Line Pattern vs. The Clean 1-Line Solution
─────────────────────────────────────────────────────────────────────────────────────────────────────────
Look at how the author handled this in `src/modules.py`:

```python
# The Author's 2-Line Approach:
x = x[:, 0, :]        # Line 1: Used integer 0 -> Collapsed 5D down to 4D (B, 3, 160, 160)
x = x[:, None, :]     # Line 2: Forced to use `None` (unsqueeze) to restore 5D (B, 1, 3, 160, 160)!
```

The author made extra work: they collapsed the axis in Line 1, only to manually re-add it in Line 2!

```python
# The Clean 1-Line Solution:
x = x[:, 0:1, :, :, :]  # Slices revisit 0 and PRESERVES the 5D shape in a single operation!
```
Shape is immediately `(B, 1, 3, 160, 160)` without collapsing or needing `None`.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
4. Quick Reference: Why `None` Adds a Dimension (The `unsqueeze` Shorthand)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
In Python, NumPy, and PyTorch, placing `None` inside square brackets `[...]` is the built-in shorthand 
for creating a new dimension of length 1 at that position.

• Origin: In NumPy, `np.newaxis is None` evaluates to `True`. PyTorch adopted the exact same standard.
• Equivalence (All 3 lines are 100% identical in PyTorch):
  1. `x[:, None, :]`            (Standard Python / NumPy shorthand)
  2. `x[:, np.newaxis, :]`      (Explicit NumPy style)
  3. `torch.unsqueeze(x, dim=1)`(Explicit PyTorch functional call)
  All three turn shape `(2, 3, 160, 160)` -> `(2, 1, 3, 160, 160)`.

• Placement Rule:
  - Front:  `x[None, ...]`      -> `(1, B, C, H, W)`
  - Middle: `x[:, None, ...]`   -> `(B, 1, C, H, W)`
  - End:    `x[..., None]`      -> `(B, C, H, W, 1)`

• Zero Memory Cost:
  Adding dimensions via `None` is a pure View operation (metadata update to `.shape` and `.strides`).
  It copies zero bytes of RAM/VRAM and executes in 0.00 milliseconds.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
5. PyTorch Interpolation Rule: Why 2D Bicubic Resizing Strictly Requires 4D Tensors (N, C, H, W)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
If Bicubic interpolation is mathematically a 2D spatial algorithm (Height x Width), why does 
`F.interpolate(..., mode='bicubic')` strictly require a 4D tensor?

• The Universal NCHW Contract:
  PyTorch requires all spatial operators to follow `(N, C, d1, d2, ...)`:
  - Dim 0 (N = Batch):    How many independent scenes are in the batch (e.g. 2 scenes).
  - Dim 1 (C = Channels): How many color layers per scene (e.g. 3 for RGB).
  - Dims 2 & 3 (H, W):    The flat 2D physical spatial grid (160 x 160) where bicubic splines run.

• Why 2D or 3D Tensors Crash:
  - 2D `(160, 160)` or 3D `(3, 160, 160)` crash with:
    `ValueError: Please provide input tensor in (N, C, d1, d2) format`.
    PyTorch refuses to guess which axis is the batch versus color channels.

• Why 5D Tensors Crash:
  - PyTorch treats 5D as a 3D volumetric medical cube: `(N, C, Depth, Height, Width)`.
  - Passing `(2, 1, 3, 160, 160)` causes PyTorch to misinterpret `3` (your RGB channels) as 3D depth!
  - It then crashes when given a 2D target size `(1054, 1054)`.

• How 4D Execution Works:
  The 2D bicubic formula executes strictly on `(H, W)`. Channels (`C`) and Batches (`N`) are never 
  mixed; each color channel of each scene is upscaled independently and in parallel on GPU threads.


═════════════════════════════════════════════════════════════════════════════════════════════════════════
   HIGHRESNET REVERSE-ENGINEERING: DEEP-DIVE INTO THE 4 CORE BUILDING BLOCKS
═════════════════════════════════════════════════════════════════════════════════════════════════════════

This technical breakdown reverse-engineers the official WorldStrat implementation (src/modules.py),
explaining exactly how each layer functions mathematically, structurally, and radiometrically.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
1. Block A: DoubleConv2d & ResidualBlock (Feature Extraction)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• What it does:
  - Two consecutive 3x3 2D convolutions with Parametric ReLU (PReLU) activations and Dropout(p=0.5).
  - Layer sequence: Conv2d(3x3) -> (BatchNorm optional) -> PReLU -> Dropout(0.5) 
                 -> Conv2d(3x3) -> (BatchNorm optional) -> PReLU -> Dropout(0.5).

• Reflection Padding (`padding_mode="reflect"`):
  - In satellite imagery, standard zero-padding inserts dark zeros around the edges of the image.
  - As convolutions slide near borders, zero-padding creates an artificial dark vignette border.
  - Reflection padding mirrors actual ground pixels across the boundary, preventing edge artifacts.

• Skip Connection (`ResidualBlock`):
  - Implements ResNet-style identity addition to preserve low-level spatial detail and prevent 
    vanishing gradients during deep backpropagation:
      x_out = x + DoubleConv2d(x)

─────────────────────────────────────────────────────────────────────────────────────────────────────────
2. Block B: OneHot & mask_encoder (Handling Atmospheric Noise & Cloud Masks)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• The Cloud Mask Problem:
  - Sentinel-2 cloud masks (CLM) are categorical classification labels with integer values 0 to 11
    (e.g., 0=No Data, 1=Saturated/Defective, 2=Dark Area, 3=Cloud Shadow, 4=Vegetation, ..., 
     8=Medium Cloud, 9=High Cloud, 10=Cirrus, 11=Snow/Ice).
  - Feeding raw integers (like 8 or 11) directly into a convolution is mathematically wrong because
    convolutions multiply by weights, implying an artificial ordinal scale (e.g. 8 < 11).

• The Encoding Pipeline:
  1. `OneHot(num_classes=12)`: Converts discrete integer labels (..., 1, H, W) into 12 binary channels:
     `(..., 12, H, W)` where each pixel has a 1.0 in its class index and 0.0 elsewhere.
  2. `DoubleConv2d(in_channels=12, out_channels=1)`: Projects the 12 categorical channels into a 
     single learned continuous representation of atmospheric interference.
  3. `nn.Sigmoid()`: Squashes the mask representation into [0.0, 1.0].
  4. Concatenation: Appended along the channel axis to the image feature maps:
     `(hidden_channels + 1)`.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
3. Block C: FusionBlock & RecursiveFusion (The "Secret Sauce" - Tournament Bracket)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Why Not Flat Temporal Concatenation (SRCNN)?
  - In SRCNN, all 8 revisits are concatenated into a flat channel stack: (8 * C).
  - The WorldStrat paper proved this is brittle: it forces early layers to memorize temporal order
    and breaks if the number of revisits changes or if dates are shuffled.

• The Tournament Bracket Fusion Mechanism (8 -> 4 -> 2 -> 1):
  Instead of merging everything at once, HighResNet uses hierarchical pairwise fusion:
  - `split(x)`: Divides the revisits into two equal halves along the time axis:
    * `first_half`  = x[:, : revisits//2]   (e.g., Revisits 0, 1, 2, 3)
    * `second_half` = x[:, revisits//2 :]   (e.g., Revisits 4, 5, 6, 7)
  - `torch.cat([first_half, second_half], dim=channels)`:
    * Pairs corresponding revisits together along the channel axis (2 * in_channels).
  - `self.fuse(x)`:
    * Passes the paired channels through `ResidualBlock` + `Conv2d` to condense (2 * in_channels)
      back down to `in_channels`.
  - Hierarchical Reduction:
    * Round 1 (Quarterfinals): 8 revisits -> 4 fused revisits
    * Round 2 (Semifinals):   4 revisits -> 2 fused revisits
    * Round 3 (Finals):       2 revisits -> 1 master synthesized feature map!
    Total fusion layers required = log2(revisits) = log2(8) = 3 layers.
  - Weight Sharing Note: The exact same `FusionBlock` instance is reused across all levels of the tree,
    enforcing recursive self-similarity and dramatically reducing total parameter count.

─────────────────────────────────────────────────────────────────────────────────────────────────────────
4. Block D: PixelShuffleBlock (Sub-Pixel Convolutional Upsampling)
─────────────────────────────────────────────────────────────────────────────────────────────────────────
• Why PixelShuffle instead of Standard Interpolation?
  - Heuristic interpolation (bilinear, bicubic) computes pixel values using fixed mathematical distance
    formulas, which inherently blurs sharp edges (roads, field boundaries, rooftops).
  - Sub-Pixel Convolution (PixelShuffle) learns convolutional filters that predict high-frequency textures
    directly in latent feature space.

• Mathematical Transformation:
  - Expands channel capacity by `r^2` (where `r` is the zoom factor):
      Channels: (C * r^2, H, W)  ──►  PixelShuffle(r)  ──►  Spatial: (C, H * r, W * r)
  - Example for 4x Super-Resolution (r=4):
    * Convolutions expand channels to `C * 16`.
    * PixelShuffle rearranges each 16-channel depth column into a 4x4 spatial pixel block.
  - Followed by convolutional refinement blocks with reflection padding and PReLU to polish 
    reconstructed edges and fine structural details.
